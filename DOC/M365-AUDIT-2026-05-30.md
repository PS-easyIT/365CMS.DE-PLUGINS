# M365 Plugin-Audit – 2026-05-30

## Scope

Geprüfte Plugin-Familie: alle `cms-m365*` Plugins im Repository, insbesondere:

- `cms-m365adminsites`
- `cms-m365azure`
- `cms-m365landing`
- `cms-m365linkcollection`
- `cms-m365matrices`
- `cms-m365tools`

## Externe Best-Practice-Quellen

- Microsoft Learn – Microsoft 365 Admin Center: Rollen, Health, Workspaces und Spezial-Admincenter.
- Microsoft Learn – Zero Trust / Identity and Access: explizit verifizieren, Least Privilege, Assume Breach, Berechtigungen regelmäßig prüfen.
- Microsoft Learn – Azure Well-Architected Framework Security: Security Readiness, Audit Trails, Schutz- und Kontrollmaßnahmen kontinuierlich validieren.
- Microsoft Learn – Azure Well-Architected Framework Performance Efficiency: Performance-Ziele, Last-/Kapazitätsplanung, Tests und langfristige Optimierung.
- MSPortals.io: Microsoft Portal-Katalog als Vergleichsquelle für Adminsites/Portal-Sammlungen.

## Audit-Schwerpunkte

- Admin-CSRF: POST-Aktionen dürfen nicht erfolgreich sein, wenn `CMS\Security` fehlt oder Token ungültig sind.
- Ausgabe-Kontexte: HTML, Attribute und JavaScript-Kontexte getrennt behandeln.
- Lokale Datenkataloge: JSON-Dateien defensiv laden, Pfade normalisieren und fehlerhafte Inhalte nicht ungeprüft weiterreichen.
- Public Performance: vorhandene Caches und begrenzte Listen beibehalten; keine zusätzlichen Fremdrequests im Public-Requestpfad.
- Admin-Einstellungen: bestehende Konfigurationsoptionen, Farb-/Layoutsteuerungen und Sichtbarkeiten beibehalten.

## Umgesetzte Fixes

| Plugin | Version | Änderung |
|---|---:|---|
| `cms-m365linkcollection` | `1.0.2` | Admin-CSRF-Fallback fail-closed; Löschdialog nutzt JSON-Encoding für Eintragsnamen im JavaScript-Kontext. |
| `cms-m365adminsites` | `1.0.1` | Admin-CSRF-Fallback fail-closed; JSON-Ausgabe im Löschdialog gegen Encoding-Fehler abgesichert. |
| `cms-m365matrices` | `1.2.1` | Admin-CSRF-Fallback fail-closed; Read-only-JSON-Lader prüft Dateiname, Lesbarkeit, Dateigröße und JSON-Fehler. |
| `cms-m365tools` | `3.0.5` | Lokaler JSON-Kataloglader mit `basename()`, Lesbarkeit-, Größen- und JSON-Fehlerprüfung gehärtet. |

## Keine Codeänderung notwendig

- `cms-m365azure`: Admin-CSRF war bereits fail-closed; Löschmodal arbeitet mit Datenattributen; Adminwerte werden zentral normalisiert.
- `cms-m365landing`: Admin-CSRF war bereits fail-closed; Farbwerte werden aus Textfeld/Farbpicker validiert; Löschmodal arbeitet mit Datenattributen.

## Validierung

- PHP-Syntaxprüfung für alle geänderten PHP-Dateien.
- JSON-Manifestprüfung für geänderte `update.json` Dateien.
- Git Whitespace-Check via `git diff --check`.
- VS-Code-Diagnoseprüfung für die geänderten PHP-Dateien.

## Folgeempfehlungen

- Bei zukünftigen Adminseiten Inline-Eventhandler vermeiden und bevorzugt Datenattribute plus dedizierte JS-Dateien nutzen.
- Public-Links aus Admin-/Seed-Daten weiterhin zentral auf `http`, `https` oder interne Pfade begrenzen.
- Größere M365-Katalogdateien weiterhin lokal cachen und nie im Public-Requestpfad remote abrufen.
